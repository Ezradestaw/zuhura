# Zuhura Mars Digital Twin — Mars Quantized-Mesh 1.0 Terrain Pipeline

**Document Version:** 1.0.0  
**Phase:** Stage 6 Implementation  
**Module:** `zuhura_data.terrain.quantized_mesh` & `prepare_jezero_terrain.py`  
**Target Area:** Jezero Crater ($18.0^\circ\text{–}19.0^\circ\text{ N}, 76.5^\circ\text{–}78.5^\circ\text{ E}$)  
**Reference Datum:** IAU/IAG 2015 Mars Biaxial Ellipsoid ($a=3,396,190\text{ m}, c=3,376,200\text{ m}$)  

---

## 1. Context and Problem Statement

Standard open-source quantized-mesh tools (such as `ctb-tile` and Cesium Ion pipelines) are hardcoded to the Earth's **WGS84 ellipsoid** ($a = 6,378,137.0\text{ m}, c = 6,356,752.3\text{ m}$).

Applying Earth WGS84 tools to Mars datasets produces severe spatial and elevation corruption:
1. **Curvature Mismatch**: Mars has nearly half the radius of Earth ($a_{\text{Mars}} \approx 3,396\text{ km}$ vs $a_{\text{Earth}} \approx 6,378\text{ km}$). Earth-projected horizon occlusion points and bounding spheres fail Cesium culling tests.
2. **Flattening Error**: Mars flattening ($f = 0.005886$) differs substantially from Earth ($f = 0.003353$).
3. **MCMF Coordinate Distortion**: Quantized-mesh vertex positions are encoded as relative offsets from tile center in Mars-Centered Mars-Fixed (MCMF) Cartesian space. Earth ellipsoid math places vertices thousands of kilometers away from the true planetary surface.

To solve this, Zuhura implements a native Mars Quantized-Mesh 1.0 encoder strictly conforming to the **IAU/IAG 2015 Mars Biaxial Ellipsoid**.

## 2. Regional Jezero DEM Extraction

The elevation substrate for the pilot terrain mesh is extracted directly from `mola_global_meg128_cog.tif`:
- **Bounding Box**: $76.5^\circ\text{–}78.5^\circ\text{ E}$, $18.0^\circ\text{–}19.0^\circ\text{ N}$ (covers Jezero crater, the western fan delta, and the surrounding crater rim).
- **Dimensions**: 256 pixels (longitude) × 128 pixels (latitude).
- **Pixel Scale**: 128 pixels/degree $\approx 463.0577\text{ m/px}$.
- **Elevation Range**: Minimum $-2,916\text{ m}$ (crater deep floor), Maximum $-514\text{ m}$ (crater rim plateau).
- **Output Artifact**: `data/processed/mola/jezero/mola_jezero_meg128.tif` with provenance manifest `jezero_terrain_provenance.json`.

## 3. Quantized-Mesh 1.0 Specification Implementation

The binary `.terrain` file generated by Zuhura adheres to the Cesium Quantized-Mesh 1.0 binary format:

### 3.1 Header (88 bytes)
All fields stored in little-endian format:
- `centerX`, `centerY`, `centerZ` (`double[3]`, 24 bytes): MCMF Cartesian center coordinates on the Mars ellipsoid.
- `minHeight`, `maxHeight` (`float[2]`, 8 bytes): Elevation bounds in meters relative to the areoid datum.
- `boundingSphereCenterX`, `boundingSphereCenterY`, `boundingSphereCenterZ`, `boundingSphereRadius` (`double[4]`, 32 bytes): Bounding sphere enclosing all vertices.
- `horizonOcclusionPointX`, `horizonOcclusionPointY`, `horizonOcclusionPointZ` (`double[3]`, 24 bytes): Occlusion culling point computed from Mars ellipsoidal normal vectors.

### 3.2 Vertex Data
Vertices are quantized to 16-bit unsigned integers $[0, 32767]$:
- $u$: Longitude fraction across tile bounds $\in [0, 1]$.
- $v$: Latitude fraction across tile bounds $\in [0, 1]$.
- $height$: Elevation fraction between `minHeight` and `maxHeight`.

The arrays (`u`, `v`, `height`) are compressed using **zig-zag delta encoding**:
$$\text{encoded}_i = \text{zig\_zag}(\text{raw}_i - \text{raw}_{i-1})$$

### 3.3 Triangle Indices
Triangle topology is generated as a regular grid triangulation ($2$ triangles per grid cell) and serialized as 16-bit unsigned integers using high-water mark delta encoding.

### 3.4 Skirt and Edge Indices
Edge vertex lists (West, South, East, North) are encoded to allow seamless mesh stitching and skirt extrusion between adjacent tiles, eliminating cracks at tile boundaries.

## 4. TMS Tile Addressing and `layer.json`

Tiles are organized according to the Tile Map Service (TMS) scheme:
```
data/tiles/terrain/jezero/
├── layer.json
└── 9/
    └── 732/
        └── 203.terrain
```

The tile $(z=9, x=732, y=203)$ corresponds to the Jezero bounding box:
$$\text{lon}_{\min} = 732 \times \frac{360}{2 \cdot 2^9} - 180 = 76.875^\circ$$
$$\text{lat}_{\min} = 203 \times \frac{180}{2^9} - 90 = -18.63^\circ \dots$$

## 5. CesiumJS Client Integration

In `zuhura-frontend`, the terrain provider is loaded asynchronously:
```typescript
import * as Cesium from 'cesium';
import { MARS_ELLIPSOID } from '../lib/cesium/marsEllipsoid';

const terrainProvider = await Cesium.CesiumTerrainProvider.fromUrl(
  '/api/v1/tiles/terrain/jezero',
  {
    ellipsoid: MARS_ELLIPSOID,
    requestVertexNormals: true,
  }
);

viewer.terrainProvider = terrainProvider;
```
Cesium inspects `layer.json`, reads the TMS bounding boxes, requests the binary `.terrain` files, and renders 3D Martian topography with hardware-accelerated shading.
